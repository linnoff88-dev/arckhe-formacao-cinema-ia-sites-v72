Lesson 4 · 15 min

Depth with Three.js without freezing the page

Video frames give you the film; Three.js gives you a scene drawn in code that changes angle as you scroll. The risk is the scene drawing nonstop, even when idle or off screen, and heating up the phone. Here you measure, in a headless Chromium, how many times the scene draws in each situation, and you watch the common mistake fail.

Start the lesson

In this lesson you will

  1. 1Draw on demand: only when the scroll progress has changed
  2. 2Density cap (1.5) and offscreen pause with IntersectionObserver
  3. 3Count the draws with Playwright: idle, scrolling, offscreen, and reduced motion
  4. 4How much Three.js weighs on the page

Goal: measure a Three.js scene that only draws when the scroll changes, pauses off screen, and respects reduced motion.

On-demand drawing: each question is a reason NOT to draw. Click each step.

The common mistake is the tutorial loop: requestAnimationFrame calling render() 60 times a second, forever.

02 · The heart of the kit scene

Page kit/site-three/index.html: four rings at different depths; the camera moves with the scroll. Three.js 0.186.1 (npm, 10/19/2026), copied into vendor/.

Excerpt · kit/site-three/index.html
      // On demand: only draws when scrolling changed the progress and the scene is on screen.
      const talvez = () => {
        pedido = false;
        if (!visivel) return;
        const p = progresso();
        if (Math.abs(p - ultimo) < 1e-4) return;
        ultimo = p; desenhar(p);
      };
      const agendar = () => { if (!pedido) { pedido = true; requestAnimationFrame(talvez); } };

03 · Measure the draws

three-medir.mjs scrolls the page in a headless Chromium and reads window.__renders in each situation.

Idle and offscreen: zero. With reduced motion: one frame only. The last two lines are the weight: 2.12 MB raw (unminified), 0.42 MB with gzip -9. Servers usually compress JS; JPEG barely compresses. Measure what will travel over the wire before comparing with the film.

FALHA: desenhou 103 vezes parado (devia ser 0)
FALHA: desenhou 81 vezes fora da tela (devia ser 0)
FALHA: com reduzir movimento desenhou 83 vezes (devia ser 1)
saída: 1

With ?sempre=1 the page turns on the tutorial loop. The numbers vary on every run; the failure does not.

04 · Video frames or Three.js?

Both fit on the same page; each does one thing well.

1. Frames

Real photo, material, hard light: what a generator or a camera does better than code.

The weight grows with the length of the film.

2. Three.js

Shapes, diagrams, particles, pieces that react to the mouse or change color: everything drawn on the fly.

The weight is the library (2.12 MB raw, 0.42 MB with gzip here) and the GPU's work on each draw.

3. Together

A frame film in the opening and a Three.js piece in a section below. Each with its own rule: frames in the bitmap window, scene on demand.

The right library for each motion piece is in course 3 (lesson 6).

05 · Practice

Measure, break, and fix.

E1 · Measure

5 min

Run the "measure the scene and the weight" block.

Done when: The line starts with OK: parado 0 · rolando (the number of draws while scrolling varies with the machine), ends with fora da tela 0 · reduzir 1 · DPR 1,5, and saída: 0 follows.

E2 · The mistake

5 min

Run the same meter with ?sempre=1 at the end of the URL (the "common mistake: always drawing" block).

Done when: Three FALHA: desenhou … lines and saída: 1.

E3 · Your scene

20 min

Copy kit/site-three to a folder of your own and swap the rings for another shape (TorusKnotGeometry, for example) and the material color. Keep the maybe function and the density cap. Serve the folder and measure.

Done when: The three-medir.mjs in your folder answers OK: parado 0 … reduzir 1 with saída: 0.
